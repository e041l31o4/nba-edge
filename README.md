# NBA EDGE

NBA 專業賽前數據研究平台（繁體中文／台灣時間 UTC+8）。

## 功能
- NBA 賽程、比分、日期切換與賽前分析。
- 台灣運彩官方盤口資料適配器：只接受官方授權、文件化的 JSON feed；不會將其他莊家資料標示成台灣運彩。
- 15 分鐘排程（需先取得官方授權 feed URL）；保留盤口快照供開盤觀測、盤中更新及賽前最後盤回溯。
- 串關研究：2–6 關組合比較、組合賠率、估計過關率、理論 EV 與模擬返還。
- 賽後逐項驗證：命中／未中／走盤；資料保存在目前瀏覽器。
- 模型績效頁不虛構歷史命中率或 ROI。


## 賽前分析模型（目前版本）
- **獨立勝率**：以最近 10 場及最近 5 場攻防表現加權（60%／40%），加入主場因素、休息天數、背靠背疲勞，以及由近期對手淨勝分推估的賽程強度修正；計算前不讀取盤口或賠率。賽程強度修正屬實驗性係數，仍須透過歷史回測驗證。
- **近期狀態與賽程密度**：顯示最近 10 場與最近 5 場戰績、場均得分／失分、淨勝分、休息天數、背靠背，以及開賽前 72 小時、5 天、7 天內的已賽場次與連續客場場次。連續客場僅是旅途負荷代理指標，不代表實際飛行里程或時區變化；賽程密度與客場連戰目前先作疲勞風險觀察，不額外加權勝率，避免在尚未完成歷史回測前引入未驗證係數。
- **傷兵與輪休風險**：優先嘗試 NBA 官方傷兵報告；若官方 PDF 無法取得或解析，改用 ESPN 公開傷兵資料並清楚標示來源。球員資料會補上球隊、位置、狀態、傷勢細節及 ESPN 可取得的賽季場均得分、上場時間、籃板、助攻、抄截、阻攻、失誤、使用率與出賽場次。模型依 Out、Doubtful、Questionable、Probable 等狀態估計缺陣機率，並以球員場均得分、場均上場時間及缺陣機率估算未被替補補上的產出；替補缺口係數依場均上場時間約 25%–45%，缺少上場時間時採 35% 保守值，單隊修正上限 10 分。沒有場均得分資料的球員不會被硬估。此係數屬保守實驗參數，尚待多季回測驗證；新增的其他球員數據目前僅供角色判讀，尚未轉換成勝率加權，避免使用未驗證的主觀係數。背靠背由球隊最近完賽日期推算；近期戰績僅採當季例行賽，排除季前賽。
- **盤口比較**：模型先產生勝率與預測比分，再計算讓分過盤率、大小分機率；盤口不會回頭影響勝負機率。
- **機率校準**：即時勝負勝率會套用前一批完整賽季訓練出的 Platt 校準器；回測採嚴格時間順序，每一季只使用更早賽季的預測與賽果訓練，再於後續賽季驗證。校準只調整勝負機率，不改變預測分差與總分，也不讀取盤口。最新跨季留出測試顯示 Brier Score 有改善，但仍須持續以前瞻賽季資料驗證；若無可用校準器則回退原始機率。
- **模型限制**：傷兵量化目前以賽季場均得分、場均上場時間及狀態缺陣機率做角色加權替補缺口估算，尚未把使用率、球員正負值、替補深度、官方預計上場時間及傷勢復出限制納入經驗證的球員價值係數；球員賽季場均也不是近期手感指標。傷兵係數仍需多季回測與敏感度分析；校準後勝率也不等同已驗證命中率或投注獲利。
- **資料更新**：近期戰績及傷兵資料由 GitHub Actions 每 15 分鐘刷新；球員場均在賽前分析頁按需載入。來源中斷時不會把缺資料顯示成「全員健康」。

## 球隊效率資料
- 球隊效率資料由 ESPN 公開 Core API 同步；目前可穩定取得的欄位依 API 回傳情況而定，包含 Pace、真實命中率及出賽場次。
- 若 Offensive Rating、Defensive Rating、Net Rating、失誤率或籃板率未由來源提供，介面會顯示缺值，不以得分平均推算或冒充效率數據。
- 真實命中率以來源回傳的百分比數值直接顯示；效率資料目前僅供觀察，不參與獨立勝率計算。

## 台灣運彩官方資料來源
官方網站提供 NBA 賽事資訊與玩法說明，但目前本專案尚未確認有可公開依賴的官方即時盤口 API。官方玩法及賽事資訊：
- https://www.sportslottery.com.tw/
- https://member2.sportslottery.com.tw/zh-tw/about-us/135

因此目前採用「授權 feed adapter」設計，不抓取登入後資料、不繞過驗證、不把非官方盤口混入官方資料。若台灣運彩或合法資料供應方提供正式 API／資料授權，請在 Repository → Settings → Secrets and variables → Actions 設定：

另提供 **JBot 第三方台灣運彩賠率資料 adapter** 作為可選備援（不是台灣運彩官方 API，也不代表官方直接供應）。若要啟用，請在 Repository → Settings → Secrets and variables → Actions 設定：
- `JBOT_API_TOKEN`：JBot 專屬 API token。
- `JBOT_POLL_INTERVAL_MINUTES`：可選 Repository Variable；預設 120 分鐘。若使用 300 次／日方案，可調整為 15；試用額度每日 20 次且為共用額度，建議維持 120 分鐘或更長。

若已設定 `SPORTSLOTTERY_FEED_URL`，系統優先使用授權 feed 並略過 JBot。JBot 資料只會在隊名可明確配對、且回傳有有效讓分／大小分市場時寫入；未配對或缺盤不會自行補值。JBot 回傳頻率約 10–20 分鐘，實際輪詢頻率仍由上述變數控制。
- `SPORTSLOTTERY_FEED_URL`：官方授權 JSON feed URL
- `SPORTSLOTTERY_API_TOKEN`：若供應方要求，填入 API token

Feed 預期回傳 JSON object，內含 `games` 陣列；每場至少包含 `home_team`、`away_team`、`commence_time`，盤口採標準化 `bookmakers[].markets[].outcomes[]` 格式，market key 使用 `spreads` 與 `totals`。未設定 feed 時，15 分鐘工作流程會安全略過，不會假裝已同步。

### 開盤／即時／賽前定義
- 首次觀測盤：NBA EDGE 第一次成功取得的官方快照；不冒稱官方真正開盤。
- 即時盤：比賽開始後取得的官方快照（若官方 feed 提供場中盤）。
- 賽前盤：開賽前最後一筆官方快照。
- 若 feed 沒有提供真正開盤時間或完整歷史，網站不會回填猜測；歷史從正式接通後開始累積。

## 歷史走勢回測
- 獨立的 walk-forward 回測每日執行，使用上一個完整 NBA 例行賽季資料。
- 每場預測只使用該場開賽前已完賽的比賽；先產生預測，再把該場賽果加入歷史，避免把未來結果洩漏進模型。
- 回測輸出勝負方向命中率、Brier Score、預測分差 MAE、預測總分 MAE 及樣本數。
- 回測不包含歷史傷兵狀態及歷史台灣運彩盤口，因此不能據此宣稱已驗證 ATS、大小分市場命中率或 ROI。
- 單一賽季回測只作為初步檢查；需要跨賽季、不同賽季階段及持續前瞻紀錄，才可評估模型穩定性。

## 預測留存與模型績效
- 網站開啟並取得有效賽前資料時，會為尚未開賽且資料足夠的賽事保存第一筆獨立模型預測；不會在賽後補造預測。
- 若同一瀏覽器之後讀取到該場正式完賽比分，系統會自動結算既有預測。
- 績效頁顯示預測筆數、已結算場次、勝負方向命中率、Brier Score 及平均分差誤差。Brier Score 越低代表機率預測越準。
- 預測帳本目前存於瀏覽器 localStorage，僅限同一瀏覽器／裝置；網站未開啟時不會背景自動記錄，清除瀏覽器資料亦會遺失。
- 讓分、大小分命中率與 ROI 必須等官方盤口格式、投注價格與結算資料可追溯後才計算，不以手動輸入或缺失資料偽造績效。

## 串關模型與驗證
- 支援 2–6 關組合，顯示組合賠率、估計過關率、理論 EV。
- 目前過關率以各關輸入機率相乘，假設選項獨立；同場相關選項會使估算失真。
- 建議先以 2 關做風險比較，不把多關高賠率誤認為高價值。
- 賽後可標記命中、未中、走盤；目前紀錄存在瀏覽器 localStorage，換裝置或清除瀏覽器資料不會同步。
- 只有累積足夠、可追溯的預測機率、盤口與正式賽果後，才應計算模型命中率與 ROI。

## 風險聲明
NBA EDGE 是運動數據研究與賽事分析工具，不提供保證獲利的投注建議。機率估計、EV 與串關結果均受模型校準、盤口變化、相關性及賽事資訊影響。
